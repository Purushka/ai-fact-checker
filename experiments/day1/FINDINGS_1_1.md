# Day 1.1 Findings — 3 真实 piyao case 的传播路径追溯

## 实验设计
- 3 个 piyao case：P019 政策类、P015 健康类、P021 社会类
- 4 路并发搜索：Bocha + Metaso + AnySearch + Bilibili API
- 每 case 2 个 query，共 8 路 × 3 case = 24 次搜索调用
- 完成时间：55.9s
- 总 traces：176（去重后 173），写入 `ground_truth.jsonl`

## 三大发现

### 1. 搜索引擎偏向"辟谣阶段"内容，原始谣言源采不到

**P019 案例**：搜到 20 条窗口内 trace，全部是 2025-11-30 起的国标解读 + 12-02/12-03 的起草单位回应转载。
原始谣言（"新国标要求金属鞍座"）的微博/抖音源没有任何一条返回。

**根因**：百度/360 等搜索引擎的 SEO 排序偏好权威/聚合站；原始谣言短视频/微博被
平台主动降权或删除；商业搜索 API（Bocha/Metaso）继承同样偏向。

**对系统设计的影响**：
- 单纯依赖商业搜索 API 拿不到"传播起源"
- 必须接入：(a) 微博/抖音/小红书原始 API 或抓取（合规问题）
  (b) Web Archive（archive.org）做历史快照查询
  (c) B 站 API（已验证可用，无需 token）

### 2. "Evergreen Myth" 不适用窗口过滤

**P015 案例**：纯净水缺微量元素 — 此类健康类谣言自 2007 年起就在
mama.cn / 39 健康网 / 大众养生网持续生产；piyao 2025-11-26 的澄清只是
对长期流传话题的官方表态，不是对单一事件的回应。

**意义**：
- 60 条 trace 几乎全在窗口外，但都是真实的相关内容
- TimelineBuilder 当前设计假设"单一事件 + 窄时间窗"，对 evergreen 类型不适用
- 需要新增 pattern：`evergreen_myth`（长期跨平台分布，无单点起源）

### 3. 快速 24h 内澄清的"现代谣言模式"

**P021 案例**：广州草皮染绿 — 仅 6 条窗口内 trace，且全部集中在 piyao
发布同日（2025-12-05）的官方/媒体响应。

**典型路径**（推断）：
1. 12-04 ~ 12-05 早晨：市民拍摄发微博/小红书（**未采到**）
2. 12-05 上午：广州白云区城管部门回应
3. 12-05 当天：光明网、网易、新浪同步报道 + piyao 收尾

**意义**：
- 现代社媒生态的辟谣周期从过去几周缩短到几小时
- 系统若要捕捉"原始谣言 → 官方回应"的完整链路，必须做到
  - 与社媒源（微博/小红书 API）实时同步
  - 否则只能事后看见"清场后"的内容
